# v1.3.3 release checkpoint

The release adds automatic retention for local source media and confirmed
published Reels. Both policies are independently configurable. Keeping completed
clips requires disabling published-Reel cleanup; completed-source cleanup never
deletes files from output.

Source cleanup uses the durable job store, keeps running and failed job media,
and protects active content and recovery consumers. Published-media cleanup
requires confirmed publication for every alias of a file and retains publication
history and receipts. Invalid consumer state and locked files defer cleanup.

The retention worker owns an independent process lease and checks every 20 seconds.
It does not invoke the Meta scheduler. Configuration changes are written atomically,
and settings responses mask stored credentials.

Validation before publication: 549 required release tests passed, 3 skipped, across
14 groups. This is the release gate rather than the entire repository suite.
Offline JavaScript and browser checks passed. The extracted installer passed an
embedded-runtime check, a real 1080x1920 FFmpeg render, full decode, Range playback,
shared-media guards, completed-source deletion and preservation of unfinished
output, active sources and publication history.

Publication procedure: build from the committed source in a clean worktree, verify
the embedded source identity and packaged files, push the source and immutable tag,
upload installer/checksum/release notes, publish the GitHub prerelease and verify
anonymous downloads against the local SHA256. No personal queue or runtime data
belongs in the source commit or installer.
